Suppose I give you a list of 3 numbers, 36, 47 and 58, and tell you to add them. You will simply add the numbers one by one until you get a final sum, which would be 141.

To a computer, you can feed the same logic,

```
SUM = 36 + 47 + 58
```

…to obtain your answer. In general form, you may write

```
SUM = a + b + c
```

Where `a`, `b`, and `c` are the input variables. But what if we want a broader general form for any quantity of numbers? 

## Generalising the Problem

Here's the actual problem: Find the sum of `N` amount of numbers in the given set.

Basically, you're given a set of numbers whose cardinality is `N`, and you're supposed to find the sum of the numbers.

Humans would just look at the set, add the numbers one by one, and get the result. But here's the problem with implementing it on a computer.

Looking at our previous example, where we did

```
SUM = a + b + c
```

But that was when we had 3 numbers i.e. we knew the quantity of numbers. In more general problem though, we have no idea because `N` is actually *changeable* i.e. it is not fixed for different types of problems.

For all we know, `N` could be anywhere between 0 and infinity, and the sum

```
SUM = a₁ + a₂ + a₃ + … + aₙ
```

But there is no way to have “… + a<sub>n</sub>” variables on a computer, so we have to think differently. 

## Insight

Instead of thinking about what we cannot do, let's think about what we can. We can add a set amount of numbers, let's say a<sub>1</sub> + a<sub>2</sub>. So let's try to break the numbers down to a function of a single sum of two numbers:

```
SUM = a₁ + a₂
```

Now, we could proceed by taking this sum variable and adding another number from the set to it:
```
SUM₂ = SUM + a₃
```

Where SUM is the initial sum of the two numbers. If we repeat this process till the end of the set, we will have a final SUM<sub>n</sub> which would be the sum of all numbers in the set.

But wait… doesn't this produce the same issue of SUM<sub>n</sub> being a “… + a<sub>n</sub>” value that a computer cannot compute? I mean, how are these two any different?

```
SUM = a₁ + a₂ + ... + aₙ
```

And

```
SUM₁ = a₁ + a₂
SUM₂ = SUM₁ + a₃
.
.
SUMₙ = SUM₍ₙ₋₁₎ + aₙ
```

Well, **there IS a difference.** And it involves recursion. We couldn't add a<sub>1</sub>, a<sub>2</sub> upto an because there was no guarantee that the iterations of an would be the same, i.e. a3 and a4 for example were not guaranteed to be the same numbers. However, the resultant SUM<sub>n</sub> is the **same function for any given value of N and a.** Which means it can be broken down to functional form:

```javascript
f(SUMₙ, n) = SUMₙ + f(SUMₙ, n-1)
```

This is great! Now we can just create a function that can run the above function. Let's lay it out on a step algorithm:

1. Initialize a variable SUM = 0 (intial value)
2. Read a list of numbers of size `N`
3. Perform the given steps `N` times:

a. Read next number from set as `a`.

b. Compute sum by adding SUM and `a`.

1. Print out SUM.

And we're done! This is the implementation of sum of a list of numbers.

## Pseudocode

This is totally optional, but let's implement our algorithm in pseudocode:

```jsx
function sum(var a:nelements; n:integer):real;
var sum,
    i: integer;
begin
    s := 0
    for i := 1 to n do
        s := s + a[i];
end            
```
